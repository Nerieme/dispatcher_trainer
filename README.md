# dispatcher_trainer_lab4

Объектная модель ядра диспетчерского тренажёра на C++17/20:
классы, инкапсуляция, конструкторы с проверкой инвариантов, RAII.

## Вариант предметной области

**Диспетчер безопасности объекта (пожаробезопасность).**

В здании есть несколько помещений (комнаты A–F), которые обслуживают
две бригады:

- **Brigade A** — базируется в **build 1**, обслуживает комнаты **A, B, C**;
- **Brigade B** — базируется в **build 2**, обслуживает комнаты **D, E, F**.

Инцидент описывает ситуацию в конкретной комнате. Диспетчер (или сценарий
в `main.cpp`) назначает на инцидент ту бригаду, которая обслуживает
соответствующее здание.

## Структура классов

| Класс            | Ответственность                                                                  |
|------------------|----------------------------------------------------------------------------------|
| `DispatchUnit`   | Ресурс диспетчера: бригада, её зона (здание) и статус                            |
| `Incident`       | Учебная ситуация: комната, здание, важность, визуальный маркер                   |
| `EventLog`       | RAII-обёртка над файлом журнала                                                  |
| `DispatchCenter` | Агрегатор состояния: хранит бригады и инциденты, выполняет назначение и закрытие |

Вспомогательные типы (`UnitStatus`, `IncidentStatus`, `Severity`, `VisualMarker`)
и функции `toString` вынесены в `DispatchTypes.hpp/.cpp`.


## Краткий отчёт по ЛР 4
1. Что реализовано

Разработано начальное объектное ядро диспетчерского тренажёра для варианта «Диспетчер безопасности объекта». Предметная модель включает четыре класса:
DispatchUnit — бригада диспетчера с идентификатором, именем, зоной (зданием) и статусом;
Incident — инцидент с идентификатором, названием комнаты, зданием, важностью и визуальным маркером;
EventLog — RAII-обёртка над файлом журнала;
DispatchCenter — агрегатор состояния, хранящий бригады и инциденты и выполняющий операции assign и closeIncident.
Вспомогательные перечисления UnitStatus, IncidentStatus, Severity, VisualMarker и функции toString вынесены в отдельный модуль DispatchTypes.
Все объявления классов находятся в include/dispatcher/... .hpp, реализации — в src/... .cpp. Консольный сценарий проверки — в src/main.cpp. Проект собирается через CMake (цель dispatcher_trainer, стандарт C++20, флаги -Wall -Wextra -Wpedantic).

Сценарий демонстрирует:
создание журнала dispatch.log;
добавление двух бригад: Brigade A (build 1) и Brigade B (build 2);
добавление двух инцидентов: room A (build 1) и room E (build 2);
выбор бригады по комнате (A/B/C → Brigade A, D/E/F → Brigade B);
назначение и закрытие инцидентов;
печать состояния центра на каждом шаге.

2. Проверки инвариантов

DispatchUnit (конструктор):
id > 0 — иначе std::invalid_argument;
name не пустое — иначе std::invalid_argument;
zone не пустое — иначе std::invalid_argument.

DispatchUnit (публичные операции):
assignToIncident не срабатывает, если incidentId <= 0, если статус не Available или если assignedIncidentId_ уже заполнен;
release возвращает статус в Available и очищает assignedIncidentId_;
setMaintenance не срабатывает, если бригада Busy (нельзя уйти в ремонт, пока занята);
setOffline переводит в Offline и сбрасывает привязку к инциденту.

Incident (конструктор):
id > 0;
title не пустое;
zone не пустое.

Incident (публичные операции):
assignUnit не срабатывает, если unitId <= 0, если статус не Open или если assignedUnitId_ уже заполнен;
close переводит статус в Closed и очищает assignedUnitId_.

DispatchCenter::assign:
проверяет существование бригады и инцидента;
проверяет, что бригада Available;
проверяет, что инцидент Open;
вызывает DispatchUnit::assignToIncident и Incident::assignUnit;
при неудаче второго шага откатывает статус бригады через release() — состояние остаётся согласованным.

DispatchCenter::closeIncident:
проверяет существование инцидента;
не даёт закрыть уже закрытый инцидент;
если у инцидента была назначенная бригада — освобождает её.

3. Где применён RAII

RAII реализован в классе EventLog:
конструктор открывает файл (std::ofstream out_{path, std::ios::app}), проверяет успех открытия и бросает std::runtime_error, если файл открыть не удалось; сразу после открытия пишет строку log opened;
метод write пишет строку в файл;
деструктор проверяет, что поток в порядке, и пишет log closed, после чего std::ofstream автоматически закрывает файл при разрушении объекта.
Копирование и перемещение EventLog запрещены (= delete для конструктора копирования, оператора присваивания, конструктора перемещения и оператора перемещения) — это защищает от случайного дублирования ресурса и двойного закрытия файла.
В DispatchCenter журнал хранится по ссылке (EventLog& log_), поэтому время жизни журнала определяется сценарием в main.cpp: объект EventLog log{"dispatch.log"}; создаётся раньше DispatchCenter center{log}; и разрушается позже, что гарантирует корректный порядок закрытия ресурсов.
Также RAII косвенно используется через стандартные контейнеры std::vector<DispatchUnit> и std::vector<Incident> внутри DispatchCenter: их деструкторы автоматически освобождают память, а ручное new/delete в коде не используется.
