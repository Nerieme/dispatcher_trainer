## Назначение

Локальное консольное ядро учебного тренажёра для диспетчера
пожарной безопасности объекта. Здание с комнатами A–F,
две бригады: Brigade A (build 1) и Brigade B (build 2).
Тренажёр хранит параметры (`smoke_level`, `temperature`,
`active_sensors`, `brigade_load`), журнал событий и поддерживает
STL-обработку, `std::optional`, `std::variant`, `std::filesystem`.

## Возможности на текущем этапе

- параметры диспетчерской ситуации и их проверка;
- журнал событий: `Info`, `OperatorAction`, `Warning`, `Alarm`;
- поиск параметра по имени (`std::optional`);
- команда оператора с результатом `CommandOk/Warning/Error` (`std::variant` + `std::visit`);
- сохранение текстового журнала через `std::filesystem` в `logs/security_session.txt`;
- STL-алгоритмы: `find_if`, `count_if`, `copy_if`, `sort`, `transform`.

9. Git позволяет фиксировать развитие проекта не как набор разрозненных файлов, а как управляемую историю изменений. В учебном проекте это даёт несколько конкретных преимуществ:

Прозрачность хода работы. Преподаватель видит не только финальный код, но и последовательность решений: когда был добавлен парсер команд, когда исправлена ошибка в проверке диапазона, когда обновлён README. Это позволяет оценить не только результат, но и процесс.

Безопасность экспериментов. Создание отдельной ветки (например, feature/history-and-readme) позволяет дорабатывать проект, не рискуя сломать основную рабочую версию. Если эксперимент не удался — ветку можно просто удалить.

Воспроизводимость. Любой коммит — это «снимок» проекта. Если через месяц понадобится вернуться к версии, которая работала на защите ЛР 9, достаточно сделать git checkout <хэш>. Это особенно важно, когда проект растёт и появляются новые лабораторные работы.

Осмысленная фиксация. Возможность делать отдельные коммиты под логически завершённые изменения (документация, исправление бага, новая функция) приучает к инженерной дисциплине и упрощает поиск причины поломки (git bisect, git log).

Разрешение конфликтов. Учебный конфликт в README показывает, как Git помогает безопасно объединять изменения из разных веток и явно фиксировать решение о том, какой текст оставить.

Таким образом, Git в учебном проекте — это не просто «хранилище файлов», а инструмент, который делает разработку управляемой, воспроизводимой и прозрачной.

## Контрольные вопросы

1. Git в учебном проекте — фиксирует историю, помогает преподавателю видеть ход работы.
2. Рабочая папка vs индекс — рабочая папка — текущие файлы, индекс — подготовленные к коммиту.
3. git status — показывает состояние рабочей папки и индекса.
4. git diff vs git diff --staged — первое сравнивает рабочую папку с индексом, второе — индекс с последним коммитом.
5. Не добавлять build/ — это артефакты сборки, они не нужны в истории.
6. .gitignore для C++/CMake — build/, out/, *.o, *.exe, .vscode/.cache/, logs/.
7. Осмысленный коммит — одно логическое изменение с понятным сообщением.
8. git add . без diff — риск закоммитить мусор (сборку, логи, временные файлы).
9. git log --oneline --decorate --graph --all — компактная история с ветками и метками.
10. Отдельная ветка — изоляция доработки, чтобы main оставался рабочим.
11. При merge — Git объединяет изменения двух веток; если нет конфликтов — fast-forward или merge-коммит.
12. Fast-forward vs merge-коммит — FF просто переносит указатель, merge-коммит создаёт новый коммит с двумя родителями.
13. Конфликт — когда обе ветки меняют одну и ту же строку.
14. Маркеры конфликта — <<<<<<<, =======, >>>>>>>.
15. После ручного исправления — git add, git commit.
16. После merge снова собрать — чтобы убедиться, что объединённый код работает.
17. README должен содержать — название, вариант, возможности, структуру, команды сборки/запуска (devcontainer + Linux VM), сценарий, ограничения.
18. Git-история и воспроизводимость — по коммитам можно повторить состояние проекта на любом шаге.
19. Отдельные коммиты — новая функция, исправление, документация — разными коммитами.
20. working tree clean — нет незакоммиченных изменений.
21. История помогает преподавателю — видно, как студент шёл к результату, а не только финальный код.
