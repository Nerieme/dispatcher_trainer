## Вариант

Диспетчер безопасности объекта. 
Параметры: `smoke_level`, `temperature`, `active_sensors`, `brigade_load`.
События журнала: Info, OperatorAction, Warning, Alarm.

## Контейнеры

| Контейнер                                      | Где используется                                 |
|------------------------------------------------|--------------------------------------------------|
| `std::vector<Parameter>`                       | список параметров в `SimulatorCore::parameters_` |
| `std::vector<Event>`                           | журнал событий в `SimulatorCore::events_`        |
| `std::unordered_map<std::string, std::size_t>` | индекс `name → позиция` в `parameterIndex_`      |
| `std::map<EventType, std::size_t>`             | статистика по типам событий                      |

## Алгоритмы STL

| Алгоритм         | Где применяется                                                                |
|------------------|--------------------------------------------------------------------------------|
| `std::find_if`   | `SimulatorCore::findParameter` (резервный путь)                                |
| `std::count_if`  | `SimulatorCore::countAlarmEvents`                                              |
| `std::copy_if`   | `SimulatorCore::filterAlarmEvents`                                             |
| `std::sort`      | `SimulatorCore::sortedLog` (сортируется копия)                                 |
| `std::transform` | `parameterNames`, `parameterLines`                                             |

## Команды меню

| Команда        | Что выводит                                               |
|----------------|-----------------------------------------------------------|
| `status`       | все параметры (name, value, unit)                         |
| `find <name>`  | результат поиска параметра по имени                       |
| `alarms`       | только тревожные события (Warning + Alarm)                |
| `count_alarms` | число тревожных событий                                   |
| `log`          | **исходный журнал** в порядке добавления (без сортировки) |
| `log_sorted`   | **отсортированная копия** журнала (priority desc, id asc) |
| `stats`        | статистика по типам событий + общее число событий         |
| `names`        | только имена параметров                                   |
| `lines`        | параметры в виде `name=value unit` + количество           |
| `help`         | справка                                                   |
| `exit`         | выход                                                     |

./build/trainer_app

## Контрольные вопросы

1. **`vector` для журнала** — важен порядок, простой обход, мало вставок в середину.
2. **`map` vs `unordered_map`** — `map` упорядочен по ключу, `unordered_map` быстрее в среднем, но порядок не гарантирован.
3. **`find_if` по vector** приемлем при малом числе параметров; индекс нужен при частом поиске и большом объёме.
4. **Индекс обновлять** — потому что позиции в `vector` меняются при добавлении/удалении, иначе индекс укажет не туда.
5. **Итератор** — обобщённый «указатель» на элемент; алгоритмы работают через пары `begin/end`, чтобы не зависеть от типа контейнера.
6. **Lambda в `find_if`** — локальный предикат, не требует отдельной функции.
7. **`count_if` vs ручной цикл** — `count_if` явно выражает намерение «посчитать по условию», меньше шансов на ошибку.
8. **Сортировать копию** — чтобы не менять исходный порядок журнала (он может быть хронологическим).
9. **Поля для сортировки** — `priority`, `id`, `type`, при наличии — время.
10. **Проверка статистики** — сумма по всем типам должна равняться `events().size()`.
11. **Не добавлять JSON/сеть/GUI** — это темы будущих ЛР, сейчас цель — STL.
12. **Связь с объектной моделью** — `SimulatorCore` использует `Parameter`/`Event` как данные, а не ломает `DispatcherModel`; полиморфизм ЛР 5 остаётся отдельно.
13. **Захват в lambda** — по значению копирует, по ссылке — риск висячей ссылки; для маленьких строк/чисел — по значению или `const&`.
14. **Побочные эффекты в lambda** — усложняют отладку и нарушают чистоту алгоритма.
15. **Циклы vs STL** — вывод на экран можно циклом; поиск/подсчёт/сортировку/преобразование — алгоритмами.
16. **`const&` в параметрах** — без копирования, с гарантией «не менять».
17. **Своя структура данных** — не нужна, если `vector`/`map`/`unordered_map` решают задачу; меньше кода — меньше ошибок.
18. **Docker devcontainer** — открыть в контейнере, `cmake -S . -B build`, `cmake --build build`.
19. **Linux VM** — те же команды, отличие только в среде (нет Docker, но GCC/Clang/CMake те же).
